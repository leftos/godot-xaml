# GXAML-53: convert rewrites paths across a project

The design for GXAML-53 (CLI convert: rewrite scene and resource paths across a project conversion), from the exploration below.

## Owner rulings

- Every `convert` run rewrites references to the files converted in that run, in every file it writes, and warns about references to them from files it does not touch, with file and line.
- `--project <root>` converts every `.tscn` and `.tres` under the root (forward, the default) or every `.xscn` and `.xres` (`--back`), rewrites the references between them, and edits `project.godot` and the scripts' path literals that name a converted file. It removes the originals once every converted file is written (`--project` always backs up the originals unless `--nobackup` is passed); plain `convert` keeps its source and warns when the source and its output share a uid.
- Scripts: every string literal in a `.gd` or `.cs` file whose whole text equals a converted path is rewritten, found by a lexer that skips comments; a runtime-built path holding a converted path is warned about.
- The briefs land on `main` one by one.

# Exploration: GXAML-53 path rewriting across a conversion

## Answer in short
- Do the rewrite on the **model**, not on text. One core helper, `XscnDocument -> XscnDocument` with an old-path -> new-path map, serves the addon's `_RenameDependencies` (parse, rewrite, write) and `convert` (convert to a document, rewrite, write). The only extra work for a pure extension rename (`.tscn` to `.xscn`) is nothing in the namespaces; a move across folders needs a namespace step (section 1).
- The CLI needs a **plan phase** before any write: decide which files will really be converted (pair clash, existing output, parse or conversion error all drop a file), build the map from only those, then rewrite and write. Today those decisions are made one file at a time in `ConvertOne`/`Place`, after text exists (ConvertCommand.cs:96-109, 175-199).
- `res://` paths need a project root: no code finds `project.godot` today. `ProjectConfig.Find` (ProjectConfig.cs:42-53) is the walk-up pattern to copy.
- `uid://` references survive a rename that moves the `.uid` sidecar (Godot loads by uid first, path is only the fallback), so only path text needs rewriting. Caveat that matters: `convert` leaves the original `.tscn` beside the new `.xscn` with the same uid (hazard, section 3).

## 1. Every place a path lives in the models

### XscnDocument (src/GodotXaml.Core/Xscn/XscnModel.cs)
Sites a rewrite must visit (each a path string, or a path inside value text):
1. `XscnSceneType.Path` (XscnModel.cs:115), the type of an instance node (`XscnNode.Type`), anywhere in the tree (children recursed), also on inline resources? No: `XscnResource.Type` cannot be a scene (XscnWriter.Elements.cs:125 throws).
2. `XscnFile.Path` (XscnModel.cs:283), a property value that is a bare file.
3. `XscnScalar` values holding `GodotPathRef` (GodotValue.cs:378: `Uid` and `Path`, either may be null) at the top or nested in arrays and dictionaries, including a typed array or dictionary's script type (`GodotTypeRef.Script`). `ValueReferences.Map` (Conversion/ValueReferences.cs:44-55, internal, same assembly) already walks exactly these and maps `GodotResourceRef`/`GodotPathRef`. It does NOT enter `Object(...)` (ValueReferences.cs:12-13, 54); a `Resource("res://...")` inside an `Object(Class, "p": ...)` value is therefore invisible to it. Decide whether the new helper enters `GodotObject` (recommended: yes for rewriting, since a path there is still a path; Godot's saver cannot write one there, so low frequency).
4. `XscnConnection.Binds` (XscnModel.cs:307ff): bind values are `GodotValue`; the converter maps them with `ValueReferences.Map` (TscnToXscn.Scene.cs:206, XscnToTscn.Scene.cs:214), so the helper must too.
5. `XscnInvalid(Text, Message)` (XscnModel.cs:296): unparsed text; cannot be rewritten safely, report as a warning when it contains a mapped path.
6. `XscnUid.Path` (XscnModel.cs:93): the `<x:Uids>` entry. Rename its Path, keep its Uid (uid moves with the file). The table's extension also decides how a scene tag reads back (XscnTreeReader.cs:190-202, `SceneTag`/`IsStemOf`: the first uid path with the tag's stem and any single extension, else `.xscn`).
7. `XscnNodeElement.InstancePlaceholder` (XscnModel.cs:187): a bare scene path; Godot keeps it as a plain string, no uid (resource_format_text.cpp:243-256). Written as `x:InstancePlaceholder` (XscnWriter.Elements.cs:214).
8. `XscnNamespace(Prefix, Folder)` (XscnModel.cs:88): not a file path but derived from scene paths' folders. See below.
Also keep in mind: `Script="res://..."` is just an `XscnFile`/`GodotPathRef` property (DECISIONS.md:113), covered by 2/3; `XscnKeyRef`/`XscnInline` carry no path of their own, but the inline `XscnResource` and `document.Resources` hold properties to recurse into.

### Namespaces and the scene tag in the writer
- Forward conversion builds one namespace per folder of every instanced scene, pre-order, prefix = last folder segment (TscnToXscn.Scene.cs:315-370, `Namespaces`/`SceneFolders` take `XscnSceneType.Path` regardless of extension).
- The writer picks a tag for a scene by looking up a namespace whose `Folder` equals the path's folder, and requires that the reader would recover the same path: tag `prefix:stem` only when `IsTagName(stem)` and `RecoveredPath(folder + stem) == path` (XscnWriter.Elements.cs:148-164); otherwise it writes `<x:Instance Name="..." Scene="path"/>` (XscnWriter.Elements.cs:141). `RecoveredPath` = first `x:Uids` path with that stem and one extension, else stem + ".xscn" (Elements.cs:164).
- Effect of a rename, by case:
  - Extension only, same folder (`ui/button.tscn` -> `ui/button.xscn`, the convert case): the folder is unchanged so the namespace stays; the tag local name (stem) is unchanged; if the `x:Uids` entry is renamed too it recovers `.xscn`, and with no entry `.xscn` is the default. The writer then emits `<ui:button/>`. Nothing extra to do.
  - A scene that is NOT converted but instanced from a converted `.xscn` (e.g. `ui/other.tscn`): recovery gives `.xscn` unless an `x:Uids` entry lists `.tscn`; with no uid in the table the writer falls back to `<x:Instance Scene="...tscn"/>` (Elements.cs:141, 156). Correct, no helper work.
  - Basename change: the tag's local name changes with the path (computed, not stored). `IsTagName` can fail (e.g. a `.` in the stem) and the writer falls back to `x:Instance`.
  - Folder change (a move, relevant to the addon, not to `convert`): the old `XscnNamespace` is stale. Needed step: compute the used folders of all scene paths after the rewrite; for each, keep the existing namespace entry if one has that folder; else re-use the prefix of an old entry whose scenes all moved there (so a hand-chosen prefix survives), else mint a free prefix with the same rule as `FreePrefix`/`PrefixOf` (TscnToXscn.Scene.cs:339-370, private static in `Context`; make them shared, e.g. an internal `SceneNamespaces` class). Drop namespaces no scene uses (the reader accepts unused ones; the writer writes all, Elements.cs:171). Open decision D3.
- The model keeps the document's `Namespaces` as data (XscnModel.cs:27-47), so the helper must return a new document with them updated; the writer will not infer them.

### TscnDocument (src/GodotXaml.Core/Tscn/TscnDocument.cs)
- `TscnExtResource.Path` (:55) and `.Uid` (:52): the only place a `.tscn` names a file by id; the uid stays, the path is rewritten.
- `TscnNode.InstancePlaceholder` (:108): a path string.
- Paths inside value text: `Resource("uid://..","res://...")` as `GodotPathRef` in node and sub-resource properties, resource properties, connection binds. (`ExtResource("id")` carries no path; it follows the ext_resource.)
- The scene's own header uid (:36) is not a reference.
- `TscnToXscn` turns an instance's ext_resource into `XscnSceneType(ext.Path)` (TscnToXscn.Scene.cs:176-181) and a non-scene ext_resource into `XscnFile` (only for `res://` paths, TscnToXscn.cs:104-105) or `Resource("...")` text; `x:Uids` entries come from ext_resources with uids (TscnToXscn.cs:67-73). `XscnToTscn` goes back with the paths unchanged (XscnToTscn.Scene.cs:96, 144, `DiscoverFile`), and guesses `type=` from the extension (XscnToTscn.cs:22-35: `.xres` and `.tres` both "Resource", `.xscn`/`.tscn` "PackedScene"). A rewrite does not change this (the pre-existing loss of a more specific `.tres` type is outside GXAML-53).

### Where to apply the rewrite so the converter's output is right
- Apply it to the **output document** of `TscnToXscn.Convert` (an `XscnDocument`) before `XscnWriter.Write` (ConvertCommand.cs:282-287), and to the **input document** of `XscnToTscn.Convert`'s result (a `TscnDocument`) or rather to the `XscnDocument` parsed at ConvertCommand.cs:295 before `XscnToTscn.Convert` (:306) for the way back. The way back needs the rewrite on the Xscn side BEFORE conversion, so ext ids are assigned by final paths (XscnToTscn `DiscoverFile` dedupes by path, XscnToTscn.cs:170-174). So ONE `XscnDocument` helper covers both directions; no `TscnDocument` rewriter is needed. (Alternative considered: a TscnDocument rewriter run before forward conversion would make the converter compute namespaces from final paths itself, but it is a second helper and the addon does not use it.) A `.tres`-to-`.xres` run is the same: the root is an `XscnResource`, helper recurses `document.Resources` and the root's properties.
- ID dedupe hazard: two distinct old paths mapped to one new path (or a mapped path equal to an unmapped existing one) makes two ext_resource ids at one path in the `.tscn` direction; the helper should report a collision rather than merge silently.

## 4. Script references (.gd and .cs)

### Textual forms
- GDScript: `preload("res://a/b.tscn")` (a constant expression: the string must be a literal), `load("res://...")`, `ResourceLoader.load("res://...")`, `get_tree().change_scene_to_file("res://...")`, `extends "res://x.gd"`, `const X = "res://..."`, `@export_file("*.tscn")` (a glob, not a path), `ResourceLoader.exists("...")`, `FileAccess`. Strings: `"..."`, `'...'`, triple `"""..."""`, raw `r"..."`, `&"..."` StringName, `^"..."` NodePath; comments `#...` to end of line.
- C#: `GD.Load<PackedScene>("res://...")`, `GD.Load("res://...")`, `ResourceLoader.Load<T>("res://...")`, `ResourceLoader.Load("res://...")`, `GetTree().ChangeSceneToFile("res://...")`, `const string X = "res://..."`. Strings: `"..."` (escapes `\"` `\\` `\uXXXX`), verbatim `@"..."` (`""` for a quote), raw `"""..."""`, interpolated `$"res://x/{n}.tscn"`, constants concatenated `"res://" + "x.tscn"`. Comments `//`, `/* */`, `///` XML docs.
- The owner's projects show the call name cannot be relied on: one wraps loads in its own cache helper, another keeps scene paths in constants, in doc comments and in error messages; so the rewrite matches a literal by its value, not by the call it is passed to.

### Cheapest correct approach
- Per-file mini lexer (about 100 lines each for C# and GDScript, in the CLI or a core `ScriptPaths` class) that yields string-literal tokens with their start and end offsets and skips comments; for each token that is a plain (non-interpolated) literal, decode escapes, and if the decoded value is exactly a key of the rewrite map, splice the new value in place of the token's content, keeping the quote style and everything else byte for byte. No parser, no regex over whole lines. A regex `"(res://[^"\\\r\n]*)"` alone is almost right but rewrites inside comments and `///` docs (the owner's cases above), and cannot tell `r"..."`, verbatim, or a quote inside a longer comment; it is acceptable only as the cheap fallback if the lexer is cut from the brief.
- Exact equality only: `"res://ui/button.tscn"` is rewritten; `"res://ui/button.tscn.import"`, a message containing the path, `"res://ui/" + name + ".tscn"`, and `$"res://ui/{n}.tscn"` are not. For non-exact literals that contain a mapped path as a substring, or an interpolated or concatenated literal ending in `.tscn`/`.tres`, emit a warning with file and line (cannot rewrite safely).
- What goes wrong: runtime-built paths (invisible, no warning possible except the heuristic above); `uid://` strings (correct to leave); `.tscn` in comments (lexer skips; the line is not warned, but a comment that quotes the old path is left stale: fine, or list under `--verbose`); relative paths (`"Scratch/X.tscn"`, resolved against something other than res://) not matched; paths with `res://./`, `res://a/../b`, or backslashes (not simplified by Godot's `simplify_path` in our compare) not matched; a literal copied into a `.tscn`-ish glob (`"*.tscn"`) not matched by equality; verbatim and raw C# strings need their own decoding; a `.gd` file with Windows CRLF line endings must keep its endings (edit by offsets, write bytes back with the original newline and BOM state; read with the same UTF-8 BOM policy as `SourceText`); generated or third-party scripts under `addons/` and `.godot/` (skip); `.cs` files outside the Godot project folder but in the same repo (a solution above `project.godot`) hold `res://` paths too (scanning is limited to files under the project root by design, say so).
- Scope of file kinds: the owner's ruling names `.gd`, `.cs`, `project.godot`. Other places that can hold such paths and are not covered (list in the brief as "not scanned", warn once): `.tres`/`.tscn` files the run does not touch (the ruling gives them as warnings), `.gdextension`, `export_presets.cfg`, `.import` files, `*.cfg`, `.csproj` (`<None Include>` of a scene), `override.cfg`, `.godot/` caches (regenerated; do not touch).
- project.godot edit: line-based, byte-exact otherwise. The file is a ConfigFile (INI with `key=value`, strings in double quotes, `;` comments, multi-line values for arrays and dictionaries). For every non-comment line, find double-quoted strings (handle `\"`), and if the content, with an optional leading `*`, equals a map key, replace it preserving the `*`. Covers `run/main_scene="res://..."`, `Name="*res://..."` autoloads, and any file-typed setting. Leaves `uid://` values alone (and could warn nothing). Godot rewrites the file in its own order on save anyway; do not reformat.

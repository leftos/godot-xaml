# godot-xaml — architecture

godot-xaml lets a Godot 4.7+ .NET project keep its scenes and resources as XAML-style `.xscn` and `.xres` files that Godot opens, edits and saves directly. The code is the metadata dump, the C# core, the Godot addon and the CLI; the language server and the editor extensions are still to come. The planned components and their order are in [`plans/v1-design.md`](plans/v1-design.md), and the settled choices in [`DECISIONS.md`](DECISIONS.md). The format itself is specified in [`format/README.md`](format/README.md). Terms used in a project sense are in the glossary in [`README.md`](README.md).

The rule that shapes it: one C# core, with no Godot dependency, owns the format; the Godot addon, the CLI and the language server are thin hosts over it.

## Layers

Each component gets an entry here in the commit that adds its project.

- **Metadata dump** (`tools/metadata-dump/`): a GDScript run by headless Godot that writes `metadata/godot-<major>.<minor>.json` from `ClassDB` and `extension_api.json`. It shares no files with the C# core; `dump.ps1` runs it and `check.gd` checks its output.
- **Metadata file** (`metadata/godot-4.7.json`): the committed output, one per Godot minor version; the core and the language server read it, never a running Godot.
- **Godot addon** (`godot/`, a Godot 4.7 .NET project, assembly `GodotXaml.Addon`): `godot/addons/godot_xaml/` is the addon's one canonical copy, the folder a game project copies beside its `PackageReference` to `GodotXaml.Core`. Its `.editorconfig` travels with the copy, so a host project's style rules raise nothing on the addon's files. Its classes are `[GlobalClass]` `[Tool]` source files, since Godot registers a global class only from the game project's own sources: `XscnFormatLoader` (reads `.xscn`, for PackedScene and its ancestors, so Open Scene and scene pickers list `.xscn`), `XresFormatLoader` (reads `.xres`, for every Resource type but PackedScene and GDExtension, so other pickers list `.xres`), `XscnFormatSaver` for both extensions, and `XscnMetadata`, the bundled metadata loaded once. A load passes the scene lookup (`GodotSceneFiles`: text through `FileAccess`, safe on loader threads), so instanced nodes come back in Godot's order; listing dependencies and saving pass none. Both loaders call `XscnLoading` (load, dependencies, renames, one load counter). The loader converts an `.xscn` or `.xres` to `.tscn`/`.tres` text in a temp file, with each relative reference first resolved against the file asked for, under the OS temp folder (`XscnLoadRoute`), loads it with Godot's own text loader, then gives each of the file's built-in sub-resources the path `res://<file>::<id>` and puts it in the resource cache (cache mode Reuse, Replace or ReplaceDeep), so a sub-resource behaves as a `.tscn`'s does. Replace and ReplaceDeep reuse a live same-class sub-resource in place, Reuse hands back a live one as it is (as Godot's text loader does), ReplaceDeep reloads external dependencies in replace mode, and a failed replace puts every moved object back at its path. `_Load` returns a Variant that Godot's generated C# dispatch copies and never disposes, so the loader disposes it, on a loader worker thread right after `_load` returns; a dropped scene then leaves the cache a frame later. The walks over the loaded resource (and the saver's) read only properties with the storage flag, so a non-exported script variable's resource is never taken over, and they dispose the Variants and containers they make but never a Godot object's C# wrapper; a sub-resource a walk read stays cached until the .NET GC collects its wrapper. A parse or conversion error fails the load with its messages. `.xres` reports its root tag's class as its type, and `GodotProjectLookups` gives the conversion the editor's file types (editor builds only) and the global script classes; its `ClassOf` and `ScriptClassOf` return null off the main thread, so a load on a worker thread falls back to the property's declared type and an `.xres` converted there carries no `script_class`. `_GetDependencies` lists what a file references in Godot's text loader format, so the editor's dependency tools, export and owner lookups see it (`XscnReferenceWalk` is the shared walk; it pushes errors only). `_RenameDependencies` rewrites the paths inside the file when it is moved or renamed in the FileSystem dock or replaced in the Dependencies dialog (`XscnPathRewriter` in the core, written through the saver's staging write); each renamed path's `x:Uids` entry (or uid in value text) takes the new file's uid, or is removed when it has none (`XscnRenameUids`), and a relative reference (`Resource("theme.xres")`, `Scene="child.xscn"`) is resolved against the file's folder and written relative again as Godot does (`GodotPathText`, a port of `path_to_file`), except that a spelling that would climb above `res://` is written absolute. An exception inside any loader virtual returns a failure value (Godot reads an escaped exception as OK) and logs `<path>: godot-xaml: the load failed:`, `… listing the dependencies failed:` or `… renaming the dependencies failed:`; a rewriter warning logs as `<path>: godot-xaml: <warning>`. The saver does the route back (`XscnSaveRoute`): Godot's own text saver writes a temp `.tscn`/`.tres` under the OS temp folder, the conversion turns it forward with `ConversionOptions.Previous` set to the file being replaced (its `x:Resources` keys are kept; a replaced file that does not parse logs a warning and keeps none), `XscnWriter` writes the text to a hidden staging file `.<guid>.<ext>.tmp` beside the target, and that is moved over it. A save with `ReplaceSubresourcePaths` to a `res://` path (the takeover) gives each built-in sub-resource the id and path `<file>::<id>` that the next load mints, on Save As, over an existing file and after a node rename or move, so a sub-resource is never read-only after Save As, keeps its undo history, and Paste keeps one object. `_Recognize` is false for a Script. A save outside the editor, where Godot's text saver writes no ext_resource uids, fills them from the uid cache, then from the file being replaced, for `res://` paths outside `res://.godot`. `_SetUid` writes the `.uid` sidecar for `.xscn`/`.xres` only, and refuses a path with no file, `RelativePaths` is not passed to the inner saver, and any failure, an escaped exception included, returns `Failed` with the reason logged. The addon is also an editor plugin (`plugin.cfg`, enabled in Project Settings > Plugins and in `godot/project.godot`): `XscnEditorPlugin` registers the export plugin `XscnExportPlugin` and nothing else, since the loaders and savers register themselves. On export `XscnExportPlugin` loads each `.xscn`/`.xres` through the loader, saves it as Godot binary at `res://.godot/exported/godot-xaml/export-<md5 of the res path>-<base name>.scn` or `.res`, and adds it with a `.remap` beside the original path, so the game loads binary with no addon code and the raw XML is not shipped; a `uid://` reference resolves through the uid cache to the original path, then the remap. A file that fails to convert logs `godot-xaml: <path>: <reason>` as an error and is skipped. In every export mode the plugin also checks that both loader scripts would be exported (the mode's own rule, then the include and exclude filters) and otherwise reports that the export would drop the loaders, naming the filter to fix. `godot/checks.ps1` runs the headless checks (`godot/checks/Checks.cs`, cases in `godot/checks/cases/`), and `godot/compare.ps1` runs the scene comparison (`godot/compare/Compare.cs`): it loads each scene fixture and its converted `.xscn` golden, and each `.tres` fixture and its converted `.xres`, and fails unless Godot sees the same scene or resource. The project references the core by `ProjectReference`, is not in `GodotXaml.slnx` (its build needs the Godot SDK), and has its own `GodotXaml.Addon.slnx` so the editor never regenerates the csproj.
- **CLI** (`src/GodotXaml.Cli`, net10.0, the .NET tool `GodotXaml.Cli`, command `godot-xaml`): a host over the core for people, agents and CI, built on System.CommandLine; the metadata ships beside it. `check` parses `.xscn`/`.xres` files and folders and prints MSBuild canonical diagnostic lines (exit 0 clean, 1 an error, 2 usage or I/O); `convert` (`ConvertCommand`) converts each file the other way and writes it beside its source, moving the uid between the `.tscn` header and the `.uid` sidecar, refusing an existing output unless `--force` or `godot-xaml.json` (`ProjectConfig`) allows it. It plans the whole run before writing, then rewrites in every file it writes each `res://` reference to a file converted in the same run, per nearest `project.godot` (`ProjectRoot`, with each segment's on-disk casing), and scans the project's other scene and resource files for references it cannot rewrite (`ReferenceScan`, which holds each file kind's quoting rules) and the project's `.gd`, `.cs` and `project.godot` files for string literals that name a converted file (`ScriptPaths` over the per-language lexers in `ScriptLexers`: comments are skipped, a C# interpolation hole's inner literals count, and a hole's format clause is text); plain `convert` only warns about scripts and `project.godot`, never writes them; `convert --project <root>` (`--back`, `--nobackup`) converts every `.tscn`/`.tres` (or `.xscn`/`.xres`) under the root as one all-or-nothing run: it stages the outputs in `<root>/.godot-xaml-staging/`, and only when every source converted backs up the originals (`OriginalsBackup`, to `<root>/.godot-xaml-backup/<stamp>/`), moves the outputs in, rewrites the scripts and `project.godot` through `ScriptPaths.Rewrite`, and removes the originals; its walks skip `<root>/addons`, dot folders, `.gdignore` folders, nested projects and folder links; a forward run leaves as text the files Godot loads before any addon (`StartupFiles`: the files named by `StartupFiles.Settings` in `project.godot`, and what they reach through ext_resources), naming each on an uncounted line; its project-level warnings are the `GXP` codes in `CliCodes`, counted but never changing the exit code, and a write failure counts as an error without stopping the run. `format` (`FormatCommand`) rewrites files in place in the canonical layout, or with `--check` only names them. Every command reads all its files before writing any, reports a problem with one file on that file's line and goes on, and writes through a temp file moved into place, except into `convert --project`'s staging folder, which is already off the target. It references the core only and is never referenced by it.
- **Editor checks** (`tools/editor-checks/`): a plugin in `addons/editor_checks/` and the scenes in `fixtures/`, which `godot/editor-checks.ps1` lays over a throwaway copy of `godot/`, to drive the real addon in a real editor.

  It proves what headless runs cannot: the dialogs, opening, saving, running, instancing, a save after the C# assembly reloads, the FileSystem dock, and Paste and Save As through the inspector and file dialog. Its fixtures live outside `godot/` because Godot.NET.Sdk compiles every `.cs` under the project folder.
- **Value grammar** (`src/GodotXaml.Core/Values/`): Godot's text syntax for a value, as `GodotValue` records read by `GodotValueReader.Read` and written by `GodotValueWriter.Write` (`ValueWriteOptions` sets compat mode). Float text is `GodotFloatFormat`, over a port of Godot's grisu2 (`Grisu2.cs`).

  It covers the whole grammar: null, bool, int, float, String, StringName, NodePath, the math and colour constructors, RID, Signal and Callable; arrays and typed arrays (`GodotArray`, `GodotTypeRef`); dictionaries and typed dictionaries (`GodotDictionary`, `GodotEntry`).

  It also covers the packed arrays (`GodotPackedBytes`, `GodotPackedInts`, `GodotPackedLongs`, `GodotPackedFloats`, `GodotPackedDoubles`, `GodotPackedStrings`, `GodotPackedReals`) with their legacy `Pool*Array` aliases; references (`GodotResourceRef` for `ExtResource` and `SubResource`, `GodotPathRef` for `Resource(...)`); and `Object(...)` (`GodotObject`, `GodotProperty`).

  Dictionaries are written in Godot's key order (`GodotKeyOrder`, internal): string keys by code point, other keys by Variant type then value, and keys Godot cannot order keep source order. `ValueWriteOptions.Compat` also decides `PackedByteArray`: a number list on, `PackedByteArray("base64")` off.

  Nesting past 512 arrays, dictionaries or objects raises `GodotValueParseException` ("Nesting is too deep"), so a hostile text cannot overflow the stack of the language server or editor. `GodotValueLexer` and `GodotValueReader.ReadAt` are internal, for the `.tscn` reader.
- **Metadata loader** (`src/GodotXaml.Core/Metadata/`): `GodotMetadata.Load` reads `metadata/godot-<minor>.json` into immutable records (`GodotClassInfo`, `GodotPropertyInfo` with a typed `Default` and `IsStored`, `GodotEnumInfo`, `GodotEnumMember`, `GodotThemeOverrideInfo`, `GodotSignalInfo`, `GodotSignalArgument`), each with its C# name. `FindDefault(cls, godotName)` returns a property's effective default for a class (`GodotPropertyDefault`: text and value) or null: none for a class with `hasDefaults` false, else from the class's own declaration, else its `defaultOverrides`, else its parent's; it throws for a class the metadata lacks.

  Lookups are `FindClass`, `FindClassByCSharpName`, `Inherits`, `FindProperty` and `FindPropertyByCSharpName` (both walk up the parents), `FindEnum` (the class's enum, then the global one) and `FindThemeOverride`. A malformed file raises `InvalidDataException` naming what is wrong. A signal whose name starts with `_` has no C# name, as Godot keeps it out of its C# API.

  Enum member names come from `GodotEnumNames` (`Names/`, internal), a port of Godot's enum naming in `bindings_generator.cpp`: shared prefix stripping, the FLAG/FLAGS and digit rules, and the global `Error` enum's forced prefix.
- **Fixture generator** (`tools/value-fixtures/`): a headless Godot 4.7.2 project that writes `tests/fixtures/values/{canonical,loose,floats,format4}/`, Godot's own bytes, never edited by hand. It shares no files with the C# core.
- **Tscn** (`src/GodotXaml.Core/Tscn/`, namespace `GodotXaml.Core.Tscn`): the `.tscn`/`.tres` document model. `TscnReader.Read` gives a `TscnDocument` (header, ext and sub resources, resource properties, nodes, connections, editables) with values as `GodotValue`s; `TscnWriter.Write` writes it back byte-identical for files Godot 4.7.2 wrote.

  `TscnWriter.FormatOf` picks format 3 or 4 as Godot's saver does. `TscnDocument.NewExtResourceId` and `NewSubResourceId` mint ids from a caller's seed in Godot's id alphabet.

  The reader rejects what Godot's text loader rejects, with Godot's error text (`TscnParseException`), and accepts what it accepts. Unknown attributes on a known tag are kept verbatim; `load_steps` is read and dropped. The writer refuses a resource document that holds nodes and a scene that holds resource properties.
- **Scene fixture generator** (`tools/scene-fixtures/`): a headless Godot 4.7.2 project that saves each case with `ResourceSaver.save` and copies the bytes to `tests/fixtures/scenes/`. It shares no files with the C# core.
- **Xscn model** (`src/GodotXaml.Core/Xscn/`, namespace `GodotXaml.Core.Xscn`): the immutable `.xscn` document model. `XscnDocument` holds namespaces, uids, the root and the resources; elements are `XscnClassType`, `XscnSceneType` or `XscnUnknownType`, with `XscnNode`, `XscnOverride`, `XscnResource`, `XscnProperty` and `XscnConnection`. Each element, property, connection and uid, and the document's two tables (`UidsLeadingComments`, `ResourcesTrailingComments` and their pairs), holds the text of its comments in `LeadingComments` or `TrailingComments`. A property value is an `XscnScalar`, `XscnFile`, `XscnKeyRef`, `XscnInline` or `XscnInvalid`. Constructors reject uninitialised arrays.

  `XscnPropertyNames` maps an attribute name to a Godot property and back (known class, unknown class through the global C# name index, dotted slash-named attributes, script properties verbatim); `AttributeName` returns null when `x:Prop` is needed.

  `XscnValueText` (`TypeOf`, `Read`, `Write`) gives each type its compact form and Godot value text otherwise; `Write` returns `XscnAttributeText` or `XscnNeedsProp`. `XscnEnumText` names enum members, .NET-style flags text and hint display names as Godot's inspector numbers them.
- **Xscn parser** (`src/GodotXaml.Core/Xscn/`): `XscnParser.Parse(text, kind, metadata)` always returns an `XscnParseResult`: a document plus its diagnostics and `HasErrors`, never throwing on bad text. `XmlText` reads the XML through GuiLabs.Language.Xml, `XmlSyntaxErrors` turns the library's errors into `GX0001`, and `XscnTreeReader` (split into `.Elements`, `.Attributes` and `.Format` partials) builds the model, using `XscnPropertyNames` and `XscnValueText` for attributes.
- **Xscn writer** (`src/GodotXaml.Core/Xscn/`): `XscnWriter.Write(document, metadata)` returns the canonical text of an `XscnDocument` (`XscnWriter.cs`, with `.Elements` and `.Properties` partials): LF, a final newline, no XML declaration, the layout and order of `DECISIONS.md`. A value equal to the metadata default is omitted on an element of a known class, except `layout_mode`, which is omitted only under a Container, and a connection is a signal attribute only in the simple case, else `x:Connect` (`XscnSignalNames`).

  A property whose attribute would not read back as itself is written as `x:Prop`; a string XML 1.0 cannot hold is `x:Prop` with `\uXXXX` escapes.
- **Diagnostics** (`src/GodotXaml.Core/Diagnostics/`): `TextSpan(start, length)`, UTF-16 offsets into a source text, for the language server; `XscnDiagnostic` (code, `XscnSeverity`, message, span) with the stable `GX` codes in `XscnCodes`; `LineMap` turns an offset into a 0-based (language server) or 1-based (loader) `LinePosition`.
- **Conversion** (`src/GodotXaml.Core/Conversion/`, namespace `GodotXaml.Core.Conversion`): model to model between `TscnDocument` and `XscnDocument`, `TscnToXscn.Convert` and `XscnToTscn.Convert`, each returning `ConversionResult<T>` with `ConversionIssue`s (stable `GXC` codes in `ConversionCodes`; an Error means the result must not be written). `TscnReferences` and `ValueReferences` count and rewrite references (inline versus `x:Resources`, `ExtResource` to `Resource("res://…")`); the way back makes ids and section order as Godot 4.7.2's text saver does (first-use ext order sorted by natural id order, post-order sub_resources, `GodotNaturalOrder`), and puts each section's properties in Godot's property order (`PropertyOrder`), because a `.tscn` sets them in file order and some depend on it. An instanced node, inherited root or `x:Override` takes its class from the instanced scene through the scene lookup (`ConversionOptions.SceneFiles`, resolved by `InstancedClasses`, cached for one conversion); with no lookup or no answer it keeps its written order. An `ext_resource` type is guessed from the extension (`XscnToTscn.TypesByExtension`: `.gdshader` is a `Shader`, `.gdshaderinc` a `ShaderInclude`). Resource files and scenes convert both ways. Forward (`TscnToXscn.Scene.cs`), nodes nest as their `parent=` paths say: a node with no type and no instance inside an instance becomes an `x:Override` that is a direct child of that instance, its path relative to it (never nested in another override), synthesised with nothing in it when a node added inside the instance, a connection or an `[editable]` needs one; one scene namespace per folder. Back (`XscnToTscn.Scene.cs`), elements are flattened in pre-order, an `x:Override`'s path taken under its instance, connections after every node, `[editable]` per editable element. A sub-resource's minted id depends on where it is used, never on its position: its site key (the element path and property it sits in, nested), or its `x:Resources` key, so an edit elsewhere keeps every other id (`SubResourceIdTests`). `XscnToTscn.Convert` sets `ConversionResult.Ids`, and the forward conversion's `Ids` follow the comment carry's rebuilt resources. Given the file it replaces (`ConversionOptions.Previous`), the forward conversion keeps each `x:Resources` key whose entry a sub_resource matches (`PreviousKeys`: first by id, an entry's id being the one `XscnToTscn.Convert(previous, metadata, …)` gives it with the same seed, the conversion the loader ran, and the type must agree; else the same type and the same `resource_name` or equal property values; the original keeps its key, so a value-equal duplicate takes `Type1`; a keyed entry now used once goes inline and drops its key), so a save changes only what changed. It also carries that document's comments onto the matching parts of the new one (`PreviousComments`: a node or override by its `x:UniqueId`, else by path, a property by name within a matched element, a connection by signal, target and method, a uid by path, an `x:Resources` entry by a kept key, the two tables' own comments, an inline resource of the same class); a part with no match loses its comments, each drop reported as a `GXC0117` warning, and the new document's structure, order and values never change. `XscnPathRewriter.Rewrite` renames file paths throughout an `XscnDocument` (scene types, file properties, paths in value text and binds, `x:Uids`, placeholders) and keeps its scene namespaces in step, for `convert` and the addon's dependency renames. Text goes through `TscnWriter` and `XscnWriter`, never through the conversion.
- **Core library** (`src/GodotXaml.Core`, net8.0): owns Godot's C# naming rules (`Names/GodotNames.cs`, a port of `modules/mono/utils/naming_utils.cpp` in the 4.7.2 source, with letter case from Godot's own tables (`GodotCase` over the generated `GodotCaseTables.g.cs`) and names handled as code points, so a character beyond U+FFFF counts once; enum members in `Names/GodotEnumNames.cs`), the value grammar, the metadata loader, the Tscn document model, the Xscn model and the Xscn parser above (its one dependency is GuiLabs.Language.Xml, for the XML syntax tree). It is packed as the NuGet package `GodotXaml.Core` (package readme `src/GodotXaml.Core/README.md`), which a game project references beside the copied addon folder, and it carries the metadata files as embedded resources, read with `GodotMetadata.LoadBundled`, since inside Godot the assembly is loaded from a stream and has no file path. The canonical writer and the `.tscn` conversion (`Conversion/`) are built, the conversion proven in C# by the round-trip tests and in Godot by the scene comparison.

  It never references a Godot assembly, and its internals are visible to `tests/GodotXaml.Core.Tests`.

## Integration Footguns

- The dump needs the console build of Godot on Windows (`Godot_console.exe`); the GUI build loses Godot's output and exit code.
- `metadata/godot-<minor>.json` is about 1.9 MB, so `.pre-commit-config.yaml` raises `check-added-large-files` to 4096 KB.
- `tests/fixtures/values/**` is `-text` in `.gitattributes` and excluded from the trailing-whitespace, end-of-file and mixed-line-ending hooks, because the files are Godot's exact bytes (no final newline, raw control characters). Regenerate them with the generator; never edit one.
- gdformat on Windows rewrites `.gd` with CRLF; `.gitattributes` keeps `*.gd` LF. The gdformat and gdlint hooks cover `tools/metadata-dump/`, `tools/value-fixtures/`, `tools/scene-fixtures/`, `tools/export-probe/` and `tools/editor-checks/`; csharpier also checks `tools/editor-checks/fixtures/ReloadProbe.cs`.
- `src/GodotXaml.Core/Names/GodotCaseTables.g.cs` is generated from Godot's `core/string/ucaps.h` by `tools/case-tables/generate.ps1`: regenerate it on a Godot bump, never edit it. It is in `.csharpierignore`, so csharpier skips it.
- The fixture generator needs the console build of Godot and fails on a double-precision build.
- `tests/fixtures/scenes/**` is Godot's exact bytes too (`tests/fixtures/** -text`, excluded from the whitespace hooks). A node's `unique_id` cannot be pinned from a script, so every run of `tools/scene-fixtures/` rewrites those numbers: regenerate only when a case changes, and commit the whole folder, except for a new case, which is copied alone from an `-OutDir` run so the other fixtures keep their `unique_id`s.

  A new fixture also goes in the three fixture lists (`SceneForwardTests.Scenes`, `SceneBackTests.Fixtures`, `SceneRoundTripTests.Fixtures`), `SceneBackTests.Inputs`, `ExpectedPairs` in `godot/compare/Compare.cs` and `$expectedFixtures` in `godot/compare.ps1`.

  A new `.tres` fixture joins `ResourceConversionTests.Fixtures` and `ResourceForwardTests.Resources`, gets a hand-written `.xres` golden in `tests/fixtures/converted/`, and joins `ExpectedPairs` and `$expectedFixtures` too.

  No fixture has `uid=`, since a script run has no editor file system to supply uids; the writer's unit test covers it.
- `godot/cases/` and the helper scripts `holder.gd`, `quoted.gd` and `tagged.gd` in `godot/` are copied from the fixtures by `godot/compare.ps1` on every run and are gitignored; never edit or commit them. The script fails on a fixture without its pair.

- The editor checks need a desktop: `.gate/desktop.toml` holds the hidden-desktop pattern, and the same exact pattern must be under `repos` and `desktop` in this PC's gate `remote.json` (`gate remote add`), or the run is not routed to a builder's hidden desktop. `.tmp/editor-checks/` is the run folder, recreated each run, so a routed run makes it on the builder.
- The addon's editor-filesystem and global-class lookups (`GodotProjectLookups.ClassOf`, `ScriptClassOf`) are main-thread only, since Godot reads those without locks; off the main thread they return null.
- A dependency rename writes a renamed path's uid from the new file, never keeps the old one: the `x:Uids` entry (or the uid in value text) is replaced, or removed when the new file has none. A relative spelling that would climb above `res://` is written absolute.
- `convert --project` deletes the originals, so its order must hold through any change: stage every output, then (only if every source converted) back up, move in, edit the scripts and `project.godot`, delete the originals. The plan refuses before staging, so a failed run changes nothing; a failure after the first move is the part-converted case, which stops and names the backup. Never delete before the copy is whole, and never let a partly converted project pass as done.
- `convert --project` leaves as text what Godot loads before `ResourceLoader::add_custom_loaders()` runs, since the addon's loaders do not exist yet: the files named by `gui/theme/custom`, `gui/theme/custom_font`, `audio/buses/default_bus_layout`, `display/mouse_cursor/custom_image`, `rendering/environment/defaults/default_environment` and `internationalization/locale/translations`, and every `.tres`/`.tscn` those reach through ext_resources (a left theme whose ext_resource was converted fails whole at startup). A new setting Godot reads before the addon must join `StartupFiles.Settings`. The CLI does not read `override.cfg`, and whether a left file matters to an export is unmeasured.
- The addon's `ConversionOptions` is one static instance shared by every loader thread: a per-load value (the scene lookup and the file's path) goes in a `with` copy, and nothing cached may live in it.
- `convert` keeps the text its plan produced while the rewrite leaves a document as it was, so `XscnPathRewriter` must set `XscnPathRewriteResult.Changed` for every change it makes, or stale text is written.
- Comparing two `convert` runs needs one fixed project path, since new ids seed from the output's full path (`ConvertCommand.SeedOf`).
- `ContainsDiagnostics` on a `Microsoft.Language.Xml` root stays false when the tree below it holds errors, so the parser's error walk cannot be skipped on that flag.
- Never dispose a Godot object's C# wrapper in the addon's walks: it is shared with other C# holders. A C# `_Load` override must dispose the Variant it returns, since Godot's generated dispatch copies it and never disposes the original (`DECISIONS.md`, "Sub-resource ids follow where they are used").
- The `godot-xaml` editor plugin must be enabled in a game project, or an export ships the raw XML instead of binary copies. The loaders ship and register in the game either way (`DECISIONS.md`, "Exported games load binary through a remap"), but a plugin-off export is neither supported nor measured.
- The loaders' `.cs` files still ship in an export (the game's assembly needs them); an include or exclude filter that drops them is reported by the plugin, and the filter must be fixed.
- A file that fails to convert is skipped and the export dialog shows "Failed.", but headless `--export-pack` still exits 0: Godot 4.7.2 gives an export plugin no way to change it, so a script must read the log for `ERROR: godot-xaml:`.

  `Xscn/` also holds the parser (`XscnParserTests`) and its diagnostics (`XscnParserErrorTests`); `Diagnostics/` holds `LineMapTests`.

  `Xscn/` also holds the writer (`XscnWriterTests`): the canonical fixtures written back byte for byte, the format pairs, and the layout, omission, `x:Prop` and refusal rules.

  `Conversion/` holds the resource conversion both ways (`ResourceConversionTests`): every `.tres` fixture back to its bytes with kept ids and after renumbering with fresh ones, Godot's section order, the inline-versus-table rule, and one test per issue code (`ResourceConversionTests.Issues.cs`). `SceneRoundTripTests` proves the scene round trip: every scene fixture there and back byte for byte with the forward pass's ids kept, and through the `.xscn` text with fresh ids after normalising, plus synthetic cases the fixtures lack (uids, id paths, `format=4`, nested and shared resources, connections and editables inside instances, a Theme's slash-named properties). `SceneForwardTests` converts each scene fixture and compares the written text with its hand-written golden in `tests/fixtures/converted/` (`GoldenXscnIsCanonical` checks each golden parses and writes back unchanged). `ResourceForwardTests` does the same for each `.tres` fixture and its `.xres` golden (`ConvertsGodotResourceToItsGoldenXres`, `GoldenXresIsCanonical`). `SceneBackTests` converts a hand-written `.xscn` for each scene fixture back and compares it with the fixture after `TscnTestNormalizer` renumbers ids; properties are compared in the order Godot wrote them. `StableKeyTests` covers the kept `x:Resources` keys of a forward conversion given `ConversionOptions.Previous`. `PreviousCommentsTests` covers the comment carry of a forward conversion given `ConversionOptions.Previous`. `SubResourceIdTests` covers the site-key ids of the way back.

  `Tscn/` holds the round trip of every scene fixture (`TscnRoundTripTests`), the document models and Godot's rejections and acceptances (`TscnReaderTests`), and the writer's layout, format switch, minted ids and refusals (`TscnWriterTests`).
- `godot/checks/`: headless checks inside Godot 4.7.2 (`Checks.cs` prints `CHECK <id> PASS|FAIL` and `DONE <passed>/<total>`): the core and its XML library load, the loader and saver register and are chosen, a parse error fails a load, an absolute OS path loads, the extension lists of the two loaders, dependencies, renames (uids, relative paths), a threaded load, the relative-spelling helper, and saves of scenes and resources (the editor path and `ResourceSaver.Save`, kept keys including an edited keyed sub-resource with no `resource_name` (`EditingAKeyedResourceKeepsItsKey`), the `.uid` sidecar, failures), which clear `user://gx-saves/` first. C33 to C45 cover sub-resources: the takeover on save (also over an existing file, after a rename, and not without the flag), the cache on load, Replace and Reuse of live sub-resources, a failed replace, a dropped scene leaving the cache, and a non-stored script variable left alone; the cases `held.gd` and `contained.xscn` serve them. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --log .tmp/godot-checks.log --slot light --timeout 1500 -- pwsh -NoProfile -File godot/checks.ps1` (`--no-markers` because the expected load failure prints Godot's `ERROR:` line).
- `godot/compare/`: the scene comparison inside Godot 4.7.2. `Compare.cs` loads each `tests/fixtures/scenes/*.tscn` and `*.tres` and its golden in `tests/fixtures/converted/` (the `.xscn` or `.xres` through the addon's loader) and compares a canonical dump of each. A scene dump holds: the packed structure, the runtime tree with stored properties and nested resources, connections with binds, and editable instances; the `property_order` fixture holds properties whose result depends on the order they are set in. A resource dump is a `resource <class>` line, then one `prop  <name>=<value>` line per stored property. It normalises only a path's extension and a built-in sub-resource's id; each side's dump is kept as `godot/cases/<name>.tscn.dump` and `.xscn.dump`, or `<name>.tres.dump` and `.xres.dump`. It prints `COMPARE <name> PASS|FAIL line <n>: …` and `DONE <passed>/<total>`, and `godot/compare.ps1` exits 0 only when every scene and resource passes. A name that is both a scene and a resource, or a file with no pair, fails as `COMPARE setup FAIL`. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --log .tmp/godot-compare.log --slot light --timeout 1500 -- pwsh -NoProfile -File godot/compare.ps1`.
- `godot/editor-checks.ps1` and `tools/editor-checks/`: the real addon in a real editor. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --log .tmp/editor-checks.log --slot heavy --timeout 1200 -- pwsh -NoProfile -File godot/editor-checks.ps1`, routed to a builder's hidden desktop.

The script builds, imports and exports each preset in `godot/export_presets.cfg` (all, selected, exclude, resources, broken, dependencies, customized), then runs `tools/export-probe/` (a GDScript-only project with no addon, so it can load only what the export made loadable) on the packs. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --log .tmp/godot-export.log --slot heavy --timeout 1800 -- pwsh -NoProfile -File godot/export.ps1`.

- `tests/fixtures/values/`: the expected value text, written by `tools/value-fixtures/` in `canonical/`, `loose/`, `floats/` and `format4/` (the saver's text with compat off); `tests/GodotXaml.Core.Tests/Values/` reads it.

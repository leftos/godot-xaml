# godot-xaml — architecture

godot-xaml lets a Godot 4.7+ .NET project keep its scenes and resources as XAML-style `.xscn` and `.xres` files that Godot opens, edits and saves directly. The code is the metadata dump, the C# core, the Godot addon, the CLI and the language server (diagnostics, formatting and hover so far); the editor extensions are still to come.

The planned components and their order are in [`plans/v1-design.md`](plans/v1-design.md), and the settled choices in [`DECISIONS.md`](DECISIONS.md). The format itself is specified in [`format/README.md`](format/README.md). Terms used in a project sense are in the glossary in [`README.md`](README.md).

The rule that shapes it: one C# core, with no Godot dependency, owns the format; the Godot addon, the CLI and the language server are thin hosts over it.

## Layers

Each component gets an entry here in the commit that adds its project.

- **Metadata dump** (`tools/metadata-dump/`): a GDScript run by headless Godot that writes `metadata/godot-<major>.<minor>.json` from `ClassDB` and `extension_api.json`. It shares no files with the C# core; `dump.ps1` runs it and `check.gd` checks its output.
- **Metadata file** (`metadata/godot-4.7.json`): the committed output, one per Godot minor version; the core and the language server read it, never a running Godot. Beside it, `metadata/docs/godot-<major>.<minor>.json` is the hover docs file: Godot's class reference as Markdown, written by `tools/class-docs/generate.ps1` from the engine's `doc/classes`, under Godot's Expat (MIT) notice (`metadata/docs/LICENSE-godot.txt`). The language server embeds it and `ClassDocs` reads it.
- **Godot addon** (`godot/`, a Godot 4.7 .NET project, assembly `GodotXaml.Addon`): `godot/addons/godot_xaml/` is the addon's one canonical copy, the folder a game project copies beside its `PackageReference` to `GodotXaml.Core`. Its `.editorconfig` travels with the copy, so a host project's style rules raise nothing on the addon's files.

  Its classes are `[GlobalClass]` `[Tool]` source files, since Godot registers a global class only from the game project's own sources: `XscnFormatLoader` (reads `.xscn`, for PackedScene and its ancestors, so Open Scene and scene pickers list `.xscn`), `XresFormatLoader` (reads `.xres`, for every Resource type but PackedScene and GDExtension, and for a global class whose native base is one of those, so other pickers list `.xres` and `ResourceLoader.Load(path, "MyRes")` reaches a script-class one), `XscnFormatSaver` for both extensions, `XscnMetadata`, the bundled metadata loaded once, and `GlobalClassSnapshot` (internal, not a registered class).

  A load passes the scene lookup (`GodotSceneFiles`: text through `FileAccess`, safe on loader threads), so instanced nodes come back in Godot's order; listing dependencies and saving pass none. Both loaders call `XscnLoading` (load, dependencies, renames, one load counter).

  The loader converts an `.xscn` or `.xres` to `.tscn`/`.tres` text in a temp file, with each relative reference first resolved against the file asked for, in the per-user temp folder `AddonTempFolder` names (`XscnLoadRoute`; `DECISIONS.md`, "The addon's temp files live in a per-user private folder"), loads it with Godot's own text loader, then gives each of the file's built-in sub-resources the path `res://<file>::<id>` and puts it in the resource cache (cache mode Reuse, Replace or ReplaceDeep), so a sub-resource behaves as a `.tscn`'s does.

  Replace and ReplaceDeep reuse a live same-class sub-resource in place, Reuse hands back a live one as it is (as Godot's text loader does), ReplaceDeep reloads external dependencies in replace mode, and a failed replace puts every moved object back at its path.

  `_Load` returns a Variant that Godot's generated C# dispatch copies and never disposes, so the loader disposes it, on a loader worker thread right after `_load` returns; a dropped scene then leaves the cache a frame later. The loader also releases its own C# wrapper of the resource it returns (only for a resource with no script, since a script may have handed that wrapper out while the file loaded), so this holds for an engine caller (the editor, GDScript) as for a C# one.

  The walks over the loaded resource (and the saver's) read only properties with the storage flag, so a non-exported script variable's resource is never taken over, and they dispose the Variants and containers they make but never a Godot object's C# wrapper; a sub-resource a walk read stays cached until the .NET GC collects its wrapper.

  A parse or conversion error fails the load with its messages. `.xres` reports its root tag's class as its type, and the global class of its root's `Script=` as its script class (`XresFormatLoader._GetResourceScriptClass`, reading the script through `XscnLoading.XresRootScript`), so typed pickers, typed drops and the FileSystem dock find a script-class `.xres` though the file stores no `script_class`. `GodotProjectLookups` gives the conversion the editor's file types (editor builds only) and the global script classes; its `ClassOf` and `ScriptClassOf` return null off the main thread, so a load on a worker thread falls back to the property's declared type and an `.xres` converted there carries no `script_class`.

  `_GetDependencies` lists what a file references in Godot's text loader format, so the editor's dependency tools, export and owner lookups see it (`XscnReferenceWalk` is the shared walk; it pushes errors only).

  `_RenameDependencies` rewrites the paths inside the file when it is moved or renamed in the FileSystem dock or replaced in the Dependencies dialog (`XscnPathRewriter` in the core, written through the saver's staging write). Each renamed path's `x:Uids` entry (or uid in value text) takes the new file's uid, or is removed when it has none (`XscnRenameUids`).

  A relative reference (`Resource("theme.xres")`, `Scene="child.xscn"`) is resolved against the file's folder and written relative again as Godot does (`GodotPathText`, a port of `path_to_file`), except that a spelling that would climb above `res://` is written absolute.

  An exception inside any loader virtual returns a failure value (Godot reads an escaped exception as OK) and logs `<path>: godot-xaml: the load failed:`, `… listing the dependencies failed:` or `… renaming the dependencies failed:`; a rewriter warning logs as `<path>: godot-xaml: <warning>`.

  The saver does the route back (`XscnSaveRoute`): Godot's own text saver writes a temp `.tscn`/`.tres` in that same folder, the conversion turns it forward with `ConversionOptions.Previous` set to the file being replaced (its `x:Resources` keys are kept; a replaced file that does not parse logs a warning and keeps none), `XscnWriter` writes the text to a hidden staging file `.<guid>.<ext>.tmp` beside the target, and that is moved over it.

  A save with `ReplaceSubresourcePaths` to a `res://` path (the takeover) gives each built-in sub-resource the id and path `<file>::<id>` that the next load mints, on Save As, over an existing file and after a node rename or move, so a sub-resource is never read-only after Save As, keeps its undo history, and Paste keeps one object. `_Recognize` is false for a Script.

  A save outside the editor, where Godot's text saver writes no ext_resource uids, fills them from the uid cache, then from the file being replaced, for `res://` paths outside `res://.godot`. `_SetUid` writes the `.uid` sidecar for `.xscn`/`.xres` only, and refuses a path with no file, `RelativePaths` is not passed to the inner saver, and any failure, an escaped exception included, returns `Failed` with the reason logged.

  The addon is also an editor plugin (`plugin.cfg`, enabled in Project Settings > Plugins and in `godot/project.godot`): `XscnEditorPlugin` registers the export plugin `XscnExportPlugin` and keeps the global class snapshot current, since the loaders and savers register themselves.

  `GlobalClassSnapshot` is an immutable copy of the project's global class list (script path to class, class to base), built on the main thread and read from any thread, because the editor asks a loader for a script class from its scan thread, where the live list cannot be read. `XscnEditorPlugin._EnterTree` rebuilds it after the editor's first scan stores the fresh list and on each `script_classes_updated`, which the plugin connects by object and method name (`new Callable(this, MethodName.OnScriptClassesUpdated)`), not as a C# event, so an assembly reload that removes the script makes the engine skip the slot as invalid and the same connection calls the plugin again once the reload gives it a new instance (`_ExitTree` disconnects only when `IsConnected`), and `XresFormatLoader`'s constructor rebuilds it on the main thread (a game run, an editor with the plugin off); off the main thread before any build, it is empty. A game that mounts a pack with `ProjectSettings.LoadResourcePack` calls `XresFormatLoader.RefreshGlobalClasses()` (public, static, main thread only; off it, it logs an error and changes nothing), because Godot refreshes its own list on a mount but re-creates no loader and emits no signal.

  On export `XscnExportPlugin` loads each `.xscn`/`.xres` through the loader, saves it as Godot binary at `res://.godot/exported/godot-xaml/export-<md5 of the res path>-<base name>.scn` or `.res`, and adds it with a `.remap` beside the original path, so the game loads binary with no addon code and the raw XML is not shipped; a `uid://` reference resolves through the uid cache to the original path, then the remap.

  The plugin writes the binary through a temporary file in that same `.godot/exported/godot-xaml/` folder, not in the OS temp folder.

  A file that fails to convert logs `godot-xaml: <path>: <reason>` as an error and is skipped.

  In every export mode the plugin also checks that both loader scripts would be exported (the mode's own rule, then the include and exclude filters) and otherwise reports that the export would drop the loaders, naming the filter to fix.

  `XscnPreviewScene.Instantiate` turns `.xscn` text into an instantiated scene for the preview server (main thread only, the caller frees the root, diagnostics returned and never logged), with scripts stripped unless the request and `godot_xaml/preview_server/allow_scripts` both allow them.
  With scripts off, `XscnPreviewReferences` classifies every reference by the file it resolves to (uid first), and `XscnPreviewInstances` redirects each text scene the preview references, at any depth, to a stripped copy in the addon's temp folder (deleted after the load), refuses a binary or unreadable scene with GXC0121, retypes typed containers of a removed script to `Object`, and drops the connections of nodes that lost a script inside instances.

  The addon will also host the preview server for the Visual Studio preview pane, off unless the project setting `godot_xaml/preview_server/enabled` is set (`DECISIONS.md`, "The preview server").

  `godot/checks.ps1` runs the headless checks (`godot/checks/Checks.cs`, cases in `godot/checks/cases/`), and `godot/compare.ps1` runs the scene comparison (`godot/compare/Compare.cs`): it loads each scene fixture and its converted `.xscn` golden, and each `.tres` fixture and its converted `.xres`, and fails unless Godot sees the same scene or resource.

  The project references the core by `ProjectReference`, is not in `GodotXaml.slnx` (its build needs the Godot SDK), and has its own `GodotXaml.Addon.slnx` so the editor never regenerates the csproj.
- **CLI** (`src/GodotXaml.Cli`, net10.0, the .NET tool `GodotXaml.Cli`, command `godot-xaml`): a host over the core for people, agents and CI, built on System.CommandLine; the metadata ships beside it. It finds a file's project and its `res://` paths through the core's `GodotXaml.Core.Projects` (`GodotProject`), keeping its own `MetadataFile`, `ProjectConfig` and `RunSceneFiles`.

  `check` parses `.xscn`/`.xres` files and folders and prints MSBuild canonical diagnostic lines (exit 0 clean, 1 an error, 2 usage or I/O); `convert` (`ConvertCommand`) converts each file the other way and writes it beside its source, moving the uid between the `.tscn` header and the `.uid` sidecar, refusing an existing output unless `--force` or `godot-xaml.json` (`ProjectConfig`) allows it.

  It plans the whole run before writing, then rewrites in every file it writes each `res://` reference to a file converted in the same run, per nearest `project.godot` (`GodotProject`, with each segment's on-disk casing).

  It scans the project's other scene and resource files for references it cannot rewrite (`ReferenceScan`, which holds each file kind's quoting rules).

  It scans the project's `.gd`, `.cs` and `project.godot` files for string literals that name a converted file (`ScriptPaths` over the per-language lexers in `ScriptLexers`: comments are skipped, a C# interpolation hole's inner literals count, and a hole's format clause is text). Plain `convert` only warns about scripts and `project.godot`, never writes them.

  `convert --project <root>` (`--back`, `--nobackup`) converts every `.tscn`/`.tres` (or `.xscn`/`.xres`) under the root as one all-or-nothing run. It stages the outputs in `<root>/.godot-xaml-staging/`, and only when every source converted backs up the originals (`OriginalsBackup`, to `<root>/.godot-xaml-backup/<stamp>/`), moves the outputs in, rewrites the scripts and `project.godot` through `ScriptPaths.Rewrite`, and removes the originals.

  Its walks skip `<root>/addons`, dot folders, `.gdignore` folders, nested projects and folder links. A forward run leaves as text the files Godot loads before any addon (`StartupFiles`: the files named by `StartupFiles.Settings` in `project.godot`, and what they reach through ext_resources and through the `.gd` and `.cs` scripts they attach), naming each on an uncounted line.

  Its project-level warnings are the `GXP` codes in `CliCodes`, counted but never changing the exit code, and a write failure counts as an error without stopping the run.

  `format` (`FormatCommand`) rewrites files in place in the canonical layout, or with `--check` only names them. Every command reads all its files before writing any, reports a problem with one file on that file's line and goes on, and writes through a temp file moved into place, except into `convert --project`'s staging folder, which is already off the target. It references the core only and is never referenced by it.
- **Language server** (`src/GodotXaml.LanguageServer`, net10.0 Exe): a host over the core that speaks LSP on stdin/stdout through StreamJsonRpc, with hand-written LSP types (`Protocol/`) and source-generated JSON. It advertises text sync (open, close, full), whole-document formatting and hover, and publishes diagnostics.

  It ships as a NativeAOT executable per platform, with the core's metadata and the class reference embedded, so a user needs no .NET install. `IsAotCompatible` keeps the trim and AOT analyzers on in every build; the publish-only properties sit under `'$(PublishAot)' == 'true'` in its csproj. The RPC methods are registered from the PolyType-generated shape of `ILanguageServerTarget` (`RpcTargetMetadata.FromShape`), not by reflection over the target.

  `tools/publish-server.ps1 -Rid <rid>` publishes one runtime identifier and zips the executable as `godot-xaml-ls-<version>-<rid>.zip`. On this machine's identifier (`-HostRid` names another, as the test seam) it then runs `tools/smoke-server.ps1`, which drives the executable over stdio. NativeAOT does not cross-compile across operating systems.

  `.github/workflows/build-server.yml` ("Build the language server") ships the six zips: on a published release, or a dispatch with `-f tag=v<version>` (the release must exist), it builds one leg per identifier on its native runner, signs and notarises the two macOS executables in the `sign-macos` job (`tools/sign-macos.ps1 -Step Sign`, then `-Step Notarise`), smoke-tests the signed zips in `smoke-signed` and attaches exactly six zips with `--clobber`. A pull request builds win-x64 and linux-x64, or all six unsigned when it touches the workflow, `publish-server.ps1` or `sign-macos.ps1`, and attaches nothing. A notarised bare executable cannot be stapled, so a Mac's first launch checks the ticket online.

  The six `MACOS_*` signing secrets live only in the `macos-signing` environment, which only `main` and `v*` tags may deploy to; that rule relies on the repository ruleset "Release tags: owner only", which restricts creating, updating and deleting `v*` tags to the repository admin. Only the `sign-macos` job names the environment, and it never runs for a pull request.

  `LanguageServerHost` owns the lifecycle (-32002 before `initialize`, -32600 after `shutdown` or on a second `initialize`; exit code 0 after `shutdown` then `exit`, else 1) and the handlers. `DiagnosticsPublisher` parses a document with `XscnParser` and publishes `textDocument/publishDiagnostics`: source `godot-xaml`, `code` the GX code, `codeDescription.href` to its heading in `docs/format/diagnostics.md` on `main` (a code-to-anchor table that `DiagnosticLinksTests` checks against the doc's headings). `didOpen` publishes at once, `didChange` after a 250 ms debounce (`IDebounceScheduler`), `didClose` publishes an empty list, and a stale parse never publishes.

  `ProjectCache` finds each document's project by walking up for `project.godot` and loads the bundled metadata for the Godot version in its `config/features`; it logs the version in use once per project, warns (`window/showMessage`) when that version is not bundled or `project.godot` cannot be read, and shows an error when the metadata fails to load. A document outside any project, or an `untitled:` one, uses the newest bundled metadata with `res://` checks off. VS Code's `file:///c%3A/...` URIs are normalised.

  `DocumentStore` holds the open buffers and is the server's `ISceneFiles`, so an open buffer overlays the disk. Logs go to `window/logMessage` and stderr, never stdout; StreamJsonRpc's transport warnings go to stderr. `FormattingHandler` answers `textDocument/formatting` with one edit to the core writer's canonical text, or none for a document with errors, an unwritable one or one changed while it ran. `HoverHandler` answers `textDocument/hover` (the server advertises `hoverProvider`) with a Markdown `csharp` signature block, then the default, the enum values or flags and the description, for the class tag, property, signal, enum value, `{Key}` or `x:` attribute under the character at the position (`XscnParser.ContextAt`), or null for `<`, `=`, quotes, spaces and a document changed while it ran. `ClassDocs` reads the hover docs file, embedded in the server executable as `docs/godot-<minor>.json`, lazily once per Godot minor; a minor without one gives hovers without descriptions, and a description is found by walking up the parent classes. `CompletionHandler` answers `textDocument/completion` (the server advertises `completionProvider` with the trigger characters `<`, `:`, `.`, space, `"` and `,`) with every name the context takes, sorted and unfiltered (the client filters), `isIncomplete` false, each item with a `textEdit` over the token at the cursor. `TagCompletions` offers node classes, the `x:` elements the reader accepts there and `<Parent>.<Property>` property elements in a node; in a property element the hint's allowed classes (minus `-` exclusions); Resource classes in `x:Resources` and at a `.xres` root; only `x:Prop` (and the root tables at the root) in a resource. `AttributeCompletions` offers stored properties, signals (on nodes), theme overrides, `Name` and the element kind's `x:` attributes, without the names already on the tag. `ValueCompletions` offers, in a class element's property value (the property found as hover finds it), the enum members over the whole value; for flags, the members not already written, over the comma-separated part the cursor is on (or inserted at the cursor when it is in the spaces beside a part, with the commas it needs); `True` and `False` for a bool; and for a resource property a `{Key}` for each root `x:Resources` entry whose class the property's hint takes, or whose class is unknown, except the entry the cursor is in.

  A completion's inserted text (`CompletionCandidate.Insert`) may differ from its label: a `{Key}` is inserted with the attribute escapes the writer uses, and a flags member with its separators; such an item carries a `filterText` of its inserted text. A value's range stays on the cursor's line, a value that starts on an earlier line gets no values, and any other value gets none.

  `NameRules` (shared with hover) finds the document's format prefix, reads a class hint's allowed and excluded classes and whether it takes a class, and names a type in C#; `StartTags` finds where start tags end and which are open at the cursor, skipping quoted values and comments. Completion of `res://` paths, scene-instance tags and `x:Connect` values is not built yet.
- **Editor checks** (`tools/editor-checks/`): a plugin in `addons/editor_checks/` and the scenes in `fixtures/`, which `godot/editor-checks.ps1` lays over a throwaway copy of `godot/` (left out at its top: the headless checks in `checks/` and `compare.ps1`'s generated copies), to drive the real addon in a real editor.

  It proves what headless runs cannot: the dialogs, opening, saving, running, instancing, a save after the C# assembly reloads, the FileSystem dock, and Paste and Save As through the inspector and file dialog. Its fixtures live outside `godot/` because Godot.NET.Sdk compiles every `.cs` under the project folder.
- **Value grammar** (`src/GodotXaml.Core/Values/`): Godot's text syntax for a value, as `GodotValue` records read by `GodotValueReader.Read` and written by `GodotValueWriter.Write` (`ValueWriteOptions` sets compat mode). Float text is `GodotFloatFormat`, over a port of Godot's grisu2 (`Grisu2.cs`).

  It covers the whole grammar: null, bool, int, float, String, StringName, NodePath, the math and colour constructors, RID, Signal and Callable; arrays and typed arrays (`GodotArray`, `GodotTypeRef`); dictionaries and typed dictionaries (`GodotDictionary`, `GodotEntry`).

  It also covers the packed arrays (`GodotPackedBytes`, `GodotPackedInts`, `GodotPackedLongs`, `GodotPackedFloats`, `GodotPackedDoubles`, `GodotPackedStrings`, `GodotPackedReals`) with their legacy `Pool*Array` aliases; references (`GodotResourceRef` for `ExtResource` and `SubResource`, `GodotPathRef` for `Resource(...)`); and `Object(...)` (`GodotObject`, `GodotProperty`).

  Dictionaries are written in Godot's key order (`GodotKeyOrder`, internal): string keys by code point, other keys by Variant type then value, and keys Godot cannot order keep source order. `ValueWriteOptions.Compat` also decides `PackedByteArray`: a number list on, `PackedByteArray("base64")` off.

  Nesting past 512 arrays, dictionaries or objects raises `GodotValueParseException` ("Nesting is too deep"), so a hostile value cannot overflow the stack of the language server or editor; the `.xscn` reader caps element nesting at 512 the same way (`GX0120`, the too-deep element and its subtree left unread). `GodotValueLexer` and `GodotValueReader.ReadAt` are internal, for the `.tscn` reader.
- **Metadata loader** (`src/GodotXaml.Core/Metadata/`): `GodotMetadata.Load` reads `metadata/godot-<minor>.json` into immutable records (`GodotClassInfo`, `GodotPropertyInfo` with a typed `Default` and `IsStored`, `GodotEnumInfo`, `GodotEnumMember`, `GodotThemeOverrideInfo`, `GodotSignalInfo`, `GodotSignalArgument`), each with its C# name.

  `FindDefault(cls, godotName)` returns a property's effective default for a class (`GodotPropertyDefault`: text and value) or null: none for a class with `hasDefaults` false, else from the class's own declaration, else its `defaultOverrides`, else its parent's; it throws for a class the metadata lacks.

  Lookups are `FindClass`, `FindClassByCSharpName`, `Inherits`, `FindProperty` and `FindPropertyByCSharpName` (both walk up the parents), `FindEnum` (the class's enum, then the global one) and `FindThemeOverride`. A malformed file raises `InvalidDataException` naming what is wrong. A signal whose name starts with `_` has no C# name, as Godot keeps it out of its C# API.

  Enum member names come from `GodotEnumNames` (`Names/`, internal), a port of Godot's enum naming in `bindings_generator.cpp`: shared prefix stripping, the FLAG/FLAGS and digit rules, and the global `Error` enum's forced prefix.
- **Fixture generator** (`tools/value-fixtures/`): a headless Godot 4.7.2 project that writes `tests/fixtures/values/{canonical,loose,floats,format4}/`, Godot's own bytes, never edited by hand. It shares no files with the C# core.
- **Tscn** (`src/GodotXaml.Core/Tscn/`, namespace `GodotXaml.Core.Tscn`): the `.tscn`/`.tres` document model. `TscnReader.Read` gives a `TscnDocument` (header, ext and sub resources, resource properties, nodes, connections, editables) with values as `GodotValue`s; `TscnWriter.Write` writes it back byte-identical for files Godot 4.7.2 wrote.

  `TscnWriter.FormatOf` picks format 3 or 4 as Godot's saver does. `TscnDocument.NewExtResourceId` and `NewSubResourceId` mint ids from a caller's seed in Godot's id alphabet.

  The reader rejects what Godot's text loader rejects, with Godot's error text (`TscnParseException`), and accepts what it accepts. Unknown attributes on a known tag are kept verbatim; `load_steps` is read and dropped. The writer refuses a resource document that holds nodes and a scene that holds resource properties.
- **Scene fixture generator** (`tools/scene-fixtures/`): a headless Godot 4.7.2 project that saves each case with `ResourceSaver.save` and copies the bytes to `tests/fixtures/scenes/`. It shares no files with the C# core.
- **Xscn model** (`src/GodotXaml.Core/Xscn/`, namespace `GodotXaml.Core.Xscn`): the immutable `.xscn` document model. `XscnDocument` holds namespaces, uids, the root and the resources; elements are `XscnClassType`, `XscnSceneType` or `XscnUnknownType`, with `XscnNode`, `XscnOverride`, `XscnResource`, `XscnProperty` and `XscnConnection`.

  Each element, property, connection and uid, and the document's two tables (`UidsLeadingComments`, `ResourcesTrailingComments` and their pairs), holds the text of its comments in `LeadingComments` or `TrailingComments`. A property value is an `XscnScalar`, `XscnFile`, `XscnKeyRef`, `XscnInline` or `XscnInvalid`. Constructors reject uninitialised arrays.

  `XscnPropertyNames` maps an attribute name to a Godot property and back (known class, unknown class through the global C# name index, dotted slash-named attributes, script properties verbatim); `AttributeName` returns null when `x:Prop` is needed.

  `XscnValueText` (`TypeOf`, `Read`, `Write`) gives each type its compact form and Godot value text otherwise, typing a property by the getter type the metadata dump records where Godot misdeclares it (`GodotPropertyInfo.ValueType`), on a known class or not, and reading a value written in the declared type too; `Write` returns `XscnAttributeText` or `XscnNeedsProp`. `XscnEnumText` names enum members, .NET-style flags text and hint display names as Godot's inspector numbers them.
- **Xscn parser** (`src/GodotXaml.Core/Xscn/`): `XscnParser.Parse(text, kind, metadata)` always returns an `XscnParseResult`: a document plus its diagnostics and `HasErrors`, never throwing on bad text. `XmlText` reads the XML through GuiLabs.Language.Xml, `XmlSyntaxErrors` turns the library's errors into `GX0001`, and `XscnTreeReader` (split into `.Elements`, `.Attributes` and `.Format` partials) builds the model, using `XscnPropertyNames` and `XscnValueText` for attributes.
- **Xscn writer** (`src/GodotXaml.Core/Xscn/`): `XscnWriter.Write(document, metadata)` returns the canonical text of an `XscnDocument` (`XscnWriter.cs`, with `.Elements` and `.Properties` partials): LF, a final newline, no XML declaration, the layout and order of `DECISIONS.md`.

  A value equal to the metadata default is omitted on an element of a known class, except `layout_mode`, which is omitted only under a Container, and a connection is a signal attribute only in the simple case, else `x:Connect` (`XscnSignalNames`).

  A property whose attribute would not read back as itself is written as `x:Prop`; a string XML 1.0 cannot hold is `x:Prop` with `\uXXXX` escapes.
- **Diagnostics** (`src/GodotXaml.Core/Diagnostics/`): `TextSpan(start, length)`, UTF-16 offsets into a source text, for the language server; `XscnDiagnostic` (code, `XscnSeverity`, message, span) with the stable `GX` codes in `XscnCodes`; `LineMap` turns an offset into a 0-based (language server) or 1-based (loader) `LinePosition`.
- **Conversion** (`src/GodotXaml.Core/Conversion/`, namespace `GodotXaml.Core.Conversion`): model to model between `TscnDocument` and `XscnDocument`, `TscnToXscn.Convert` and `XscnToTscn.Convert`, each returning `ConversionResult<T>` with `ConversionIssue`s (stable `GXC` codes in `ConversionCodes`; an Error means the result must not be written).

  `TscnReferences` and `ValueReferences` count and rewrite references (inline versus `x:Resources`, `ExtResource` to `Resource("res://…")`). The way back makes ids and section order as Godot 4.7.2's text saver does: first-use ext order sorted by natural id order, post-order sub_resources, `GodotNaturalOrder`.

  A node's ext_resources are numbered in the order its section writes its properties, Godot's property-list order, while sub-resource and `.tres` discovery keeps the sorted-name order of `_find_resources`, and a node of no known class keeps its written order for both. The way back also puts each section's properties in Godot's property order (`PropertyOrder`), because a `.tscn` sets them in file order and some depend on it.

  An instanced node, inherited root, `x:Override` or `InstancePlaceholder` takes its class from the instanced scene's root through the scene lookup (`ConversionOptions.SceneFiles`, resolved by `InstancedClasses`, cached for one conversion); with no lookup or no answer it keeps its written order, and a placeholder scene that cannot be read gives warning GXC0118.

  The same lookup reads a ShaderMaterial's `shader` and a MeshInstance3D's `mesh` when they are external files, so `shader_parameter/` and `blend_shapes/` come back in the shader's uniform order and the mesh's blend-shape order (`SourceOrders`, `ShaderUniforms`, cached for one conversion).

  A mesh file is a text `.tres` or, by the key the host serves it under, the `.xres` converted in the same run; a file that is missing or does not parse gives warning GXC0122, once per file and reason, reported after the sort of the first section that meets it.

  An `ext_resource` type is guessed from the extension (`XscnToTscn.TypesByExtension`: `.gdshader` is a `Shader`, `.gdshaderinc` a `ShaderInclude`).

  Resource files and scenes convert both ways. Forward (`TscnToXscn.Scene.cs`), nodes nest as their `parent=` paths say: a node with no type and no instance inside an instance becomes an `x:Override` that is a direct child of that instance, its path relative to it (never nested in another override), synthesised with nothing in it when a node added inside the instance, a connection or an `[editable]` needs one; one scene namespace per folder.

  Back (`XscnToTscn.Scene.cs`), elements are flattened in pre-order, an `x:Override`'s path taken under its instance, connections after every node, `[editable]` per editable element.

  A sub-resource's minted id depends on where it is used, never on its position: its site key (the element path and property it sits in, nested), or its `x:Resources` key, so an edit elsewhere keeps every other id (`SubResourceIdTests`). `XscnToTscn.Convert` sets `ConversionResult.Ids`, and the forward conversion's `Ids` follow the comment carry's rebuilt resources.

  Given the file it replaces (`ConversionOptions.Previous`), the forward conversion keeps each `x:Resources` key whose entry a sub_resource matches (`PreviousKeys`), so a save changes only what changed.

  A match is first by id, an entry's id being the one `XscnToTscn.Convert(previous, metadata, …)` gives it with the same seed (the conversion the loader ran), and the type must agree; else it is the same type and the same `resource_name` or equal property values. The original keeps its key, so a value-equal duplicate takes `Type1`; a keyed entry now used once goes inline and drops its key.

  It also carries that document's comments onto the matching parts of the new one (`PreviousComments`). The parts it matches are a node or override by its `x:UniqueId`, else by path, a property by name within a matched element, a connection by signal, target and method, a uid by path, an `x:Resources` entry by a kept key, the two tables' own comments, and an inline resource of the same class.

  A part with no match loses its comments, each drop reported as a `GXC0117` warning, and the new document's structure, order and values never change.

  `XscnPathRewriter.Rewrite` renames file paths throughout an `XscnDocument` (scene types, file properties, paths in value text and binds, `x:Uids`, placeholders) and keeps its scene namespaces in step, for `convert` and the addon's dependency renames. Text goes through `TscnWriter` and `XscnWriter`, never through the conversion.
- **Core library** (`src/GodotXaml.Core`, net8.0): owns Godot's C# naming rules, the value grammar, the metadata loader, the Tscn document model, the Xscn model and the Xscn parser above (its one dependency is GuiLabs.Language.Xml, for the XML syntax tree).

  The naming rules are `Names/GodotNames.cs`, a port of `modules/mono/utils/naming_utils.cpp` in the 4.7.2 source, with letter case from Godot's own tables (`GodotCase` over the generated `GodotCaseTables.g.cs`) and names handled as code points, so a character beyond U+FFFF counts once; enum members are in `Names/GodotEnumNames.cs`.

  It is packed as the NuGet package `GodotXaml.Core` (package readme `src/GodotXaml.Core/README.md`), which a game project references beside the copied addon folder, and it carries the metadata files as embedded resources, read with `GodotMetadata.LoadBundled`, since inside Godot the assembly is loaded from a stream and has no file path.

  The canonical writer and the `.tscn` conversion (`Conversion/`) are built, the conversion proven in C# by the round-trip tests and in Godot by the scene comparison.

  `Projects/` (namespace `GodotXaml.Core.Projects`) holds the file-system helpers the CLI and the language server share, still Godot-free: `GodotProject` finds a file's `project.godot` root and maps between disk paths and `res://` paths in on-disk casing, and `GodotProjectVersion.Read` takes the Godot minor from `project.godot`'s `config/features`, which `GodotMetadata.LoadBundledForProject` turns into bundled metadata.

  It never references a Godot assembly, and its internals are visible to `tests/GodotXaml.Core.Tests`.

## Integration Footguns

- The dump needs the console build of Godot on Windows (`Godot_console.exe`); the GUI build loses Godot's output and exit code.
- `metadata/godot-<minor>.json` is over 2 MB, so `.pre-commit-config.yaml` raises `check-added-large-files` to 4096 KB.
- The hover docs file stays in `metadata/docs/`, outside the Core project's `metadata/godot-*.json` embed glob (which does not recurse): a docs file beside the metadata would be embedded and listed by `GodotMetadata.BundledVersions` as a Godot version.
- `tests/fixtures/values/**` is `-text` in `.gitattributes` and excluded from the trailing-whitespace, end-of-file and mixed-line-ending hooks, because the files are Godot's exact bytes (no final newline, raw control characters). Regenerate them with the generator; never edit one.
- gdformat on Windows rewrites `.gd` with CRLF; `.gitattributes` keeps `*.gd` LF. The gdformat and gdlint hooks cover `tools/metadata-dump/`, `tools/value-fixtures/`, `tools/scene-fixtures/`, `tools/export-probe/` and `tools/editor-checks/`; csharpier also checks `tools/editor-checks/fixtures/ReloadProbe.cs`.
- `src/GodotXaml.Core/Names/GodotCaseTables.g.cs` is generated from Godot's `core/string/ucaps.h` by `tools/case-tables/generate.ps1`: regenerate it on a Godot bump, never edit it. It is in `.csharpierignore`, so csharpier skips it.
- The fixture generator needs the console build of Godot and fails on a double-precision build.
- `tests/fixtures/scenes/**` is Godot's exact bytes too (`tests/fixtures/** -text`, excluded from the whitespace hooks). A node's `unique_id` cannot be pinned from a script, so every run of `tools/scene-fixtures/` rewrites those numbers: regenerate only when a case changes, and commit the whole folder, except for a new case, which is copied alone from an `-OutDir` run so the other fixtures keep their `unique_id`s.

  A new fixture also goes in the fixture lists (`SceneForwardTests.Scenes`, `SceneBackTests.Fixtures`, `SceneRoundTripTests.Fixtures`); a hand-written back-test input goes in `SceneBackTests.Inputs`, and a fixture without one is read back from its golden `.xscn`; `godot/compare.ps1` counts the fixture files itself and passes the count to the compare scene.

  A new `.tres` fixture joins `ResourceConversionTests.Fixtures` and `ResourceForwardTests.Resources`, gets an `.xres` golden in `tests/fixtures/converted/` (written by the CLI's `convert`, as `godot-xaml convert <fixture>.tres` and the `.xres` moved there, and checked by `ResourceForwardTests`). `ResourceBackTests` converts each golden's text back and compares it with the `.tres` Godot saved, as `SceneBackTests` does for scenes; `ResourceConversionTests` round-trips in memory, which keeps Godot's order and so cannot show an order bug on the way back.

  No fixture has `uid=`, since a script run has no editor file system to supply uids; the writer's unit test covers it.
- `godot/cases/` and the helper scripts `holder.gd`, `quoted.gd` and `tagged.gd` in `godot/` are copied from the fixtures by `godot/compare.ps1` on every run and are gitignored; never edit or commit them. The script fails on a fixture without its pair.

- The editor checks need a desktop: `.gate/desktop.toml` holds the hidden-desktop pattern, and the same exact pattern must be under `repos` and `desktop` in this PC's gate `remote.json` (`gate remote add`), or the run is not routed to a builder's hidden desktop. `.tmp/editor-checks/` is the run folder, recreated each run, so a routed run makes it on the builder.
- The addon's editor-filesystem and global-class lookups (`GodotProjectLookups.ClassOf`, `ScriptClassOf`) are main-thread only, since Godot reads those without locks; off the main thread they return null.
- A script-class change reaches an `.xres` only through `GlobalClassSnapshot`, which is rebuilt at plugin start, on each `script_classes_updated` and by the loader's constructor, and by the game's call to `XresFormatLoader.RefreshGlobalClasses()` after it mounts a pack: a new path that changes the global class list without one of those leaves the snapshot stale.
- A dependency rename writes a renamed path's uid from the new file, never keeps the old one: the `x:Uids` entry (or the uid in value text) is replaced, or removed when the new file has none. A relative spelling that would climb above `res://` is written absolute.
- `convert --project` deletes the originals, so its order must hold through any change: stage every output, then (only if every source converted) back up, move in, edit the scripts and `project.godot`, delete the originals. The plan refuses before staging, so a failed run changes nothing; a failure after the first move is the part-converted case, which stops and names the backup. Never delete before the copy is whole, and never let a partly converted project pass as done.
- `convert --project` leaves as text what Godot loads before `ResourceLoader::add_custom_loaders()` runs, since the addon's loaders do not exist yet.

  Those are the files named by `gui/theme/custom`, `gui/theme/custom_font`, `audio/buses/default_bus_layout`, `display/mouse_cursor/custom_image`, `rendering/environment/defaults/default_environment` and `internationalization/locale/translations`, and every `.tres`/`.tscn` those reach through ext_resources, and every file a left file's `.gd` or `.cs` script names by a `res://` or `uid://` string literal, transitively.

  A left theme whose ext_resource was converted fails whole at startup. A `.cs` script is followed too as a conservative choice, since a wrongly left file only stays text while a wrongly converted one breaks the game.

  A new setting Godot reads before the addon must join `StartupFiles.Settings`. The CLI does not read `override.cfg`, and whether a left file matters to an export is unmeasured.
- The addon's `ConversionOptions` is one static instance shared by every loader thread: a per-load value (the scene lookup and the file's path) goes in a `with` copy, and nothing cached may live in it.
- Make Local and inspector drag-and-drop give a scene another scene's built-in sub-resources without duplicating them, so the saver tells its own sub-resources apart by their `<file>::<id>` path (`ConversionOptions.OwnedSubResourceIds`). Another file's save takes a borrowed one over and renames its path, as Godot's text saver does, and nothing the saver receives names the file a tree came from, so a path that names another file falls back to the file and id the load recorded (`SubResourceOrigins`), which only a load writes.
- `convert` keeps the text its plan produced while the rewrite leaves a document as it was, so `XscnPathRewriter` must set `XscnPathRewriteResult.Changed` for every change it makes, or stale text is written.
- `convert` seeds new ids from the source's `res://` path with the output's extension (`ConvertCommand.SeedKeyOf`), so one project converts to the same ids in any checkout; a file with no `project.godot` above it is seeded from its output's full path, and only then do two runs need one fixed path to compare.
- `ContainsDiagnostics` on a `Microsoft.Language.Xml` root stays false when the tree below it holds errors, so the parser's error walk cannot be skipped on that flag.
- Never dispose a Godot object's C# wrapper in the addon's walks: it is shared with other C# holders. A C# `_Load` override must dispose the Variant it returns, since Godot's generated dispatch copies it and never disposes the original (`DECISIONS.md`, "Sub-resource ids follow where they are used").
- Every `Variant`, `StringName`, `NodePath` and Godot `Array` or `Dictionary` the addon makes is disposed in the call that made it, including the implicit ones: a string literal passed as a `StringName` or used as a Dictionary key (keep those as `static readonly` fields), a typed `Array<T>` (cast to `Godot.Collections.Array` to dispose it), each enumerated item and each value read out of a Dictionary. GodotSharp disposes at shutdown only what is still reachable (`modules/mono/glue/GodotSharp/GodotSharp/Core/DisposablesTracker.cs`, `OnGodotShuttingDown`) and nothing drains the finalizers before the engine is torn down (`main/main.cpp`, `Main::cleanup`), so a late finalizer can crash the process. Object wrappers stay the exception the bullet above names; why: `DECISIONS.md`, "The addon disposes what it makes, not at shutdown".
- The `godot-xaml` editor plugin must be enabled in a game project, or an export ships the raw XML instead of binary copies. The loaders ship and register in the game either way (`DECISIONS.md`, "Exported games load binary through a remap"), but the exported game still loads that XML through the shipped loaders, several times slower than the binary copy and with a costly first load, and a game whose export drops the loaders' scripts cannot load it at all; it is a fallback, not a supported setup.
- The loaders' `.cs` files still ship in an export (the game's assembly needs them); an include or exclude filter that drops them is reported by the plugin, and the filter must be fixed.
- A file that fails to convert is skipped and the export dialog shows "Failed.", but headless `--export-pack` still exits 0: Godot 4.7.2 gives an export plugin no way to change it, so a script must read the log for `ERROR: godot-xaml:`.
- The editor's scene-groups cache loads every non-`.tscn` scene in full: `PackedScene::get_scene_groups` (`scene/resources/packed_scene.cpp`) reads only an extension of exactly `tscn` as text and calls `ResourceLoader::load` for any other. It is called from `EditorFileSystem::_update_scene_groups` (`editor/file_system/editor_file_system.cpp`) on the main thread: at the first start without `.godot/scene_groups_cache.cfg`, after a scan, and on each save and `update_file`.

  It never runs headless (`EditorFileSystem::_process_update_pending` skips it in `EditorNode::is_cmdline_mode`), so `checks.ps1` and `--import` never show it; the windowed editor checks do, at their start. `ResourceFormatLoader` has no hook for it in 4.7.2, and the cache's `ProjectSettings` methods are not bound. A sweep costs about ten times what the same scenes cost as `.tscn`, nearly all of it in `_Load`, and the walk's sub-resources stay alive after it until the GC runs. Why no workaround: `DECISIONS.md`, "The editor reads scene groups by loading every `.xscn`".

- `godot/editor-checks.ps1` and `tools/editor-checks/`: the real addon in a real editor. The script builds, imports and reimports the project, runs the editor with the plugin (`--xscn-editor-checks=run`) and reopens it (`reopen`), and prints `STEP build|import|reimport|editor-run|editor-reopen`, the echoed `CHECK` lines, `DONE` and `EDITOR-CHECKS passed <p>, failed <f>, expected <n>`. It echoes each editor's stderr and fails on any line starting with `ERROR: `, `SCRIPT ERROR: ` or `SHADER ERROR: ` (case-sensitive; warnings stay informational), printing `STEP editor-<mode> engine errors: <n>` and the `ENGINE-ERROR editor-<mode> <kind> <line>` lines (`<kind>` is `ERROR`, `SCRIPT-ERROR` or `SHADER-ERROR`) after that editor's exit line; the script scans because the exit errors come after the plugin's `DONE`.

  E1 covers the dialogs' extension lists, E2 opening, E8 reopening in a fresh editor and reading what was saved, E3 edit and save, E4 running the scene, E5 instancing into a `.tscn`, E6 a save after the C# assembly reloads, E7 a rename in the FileSystem dock with an `.xscn` that instances the file, E9 Paste through `EditorResourcePicker` sharing the object, E10 Save As through the file dialog leaving the sub-resource editable, E11 renaming an open scene moving its sub-resources' paths, E12 deleting a global-class script in the FileSystem dock so that an `.xres` of that class is no longer found as that class on the dock's first `script_classes_updated` (it runs last, after E6's assembly reload, so it also shows the hook still works after a reload).

  E12 deletes through the dock's Remove dialog, which sends the file to the Recycle Bin (`OS::move_to_trash`), so each run leaves one `E12Named.gd` in the running account's Recycle Bin, outside the run folder.

  The run folder is `.tmp/editor-checks/{run,results}`; `results/results.txt` holds the results, with screenshots and scene copies beside it on the machine that ran it. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --log .tmp/editor-checks.log --slot heavy --timeout 1200 -- pwsh -NoProfile -File godot/editor-checks.ps1`, routed to a builder's hidden desktop.
- `godot/export.ps1` and `tools/export-probe/`: the export proof. The script builds, imports and exports each preset in `godot/export_presets.cfg` (all, selected, exclude, resources, broken, dependencies, customized), then runs `tools/export-probe/` (a GDScript-only project with no addon, so it can load only what the export made loadable) on the packs.

  It prints `EXPORT <id> PASS|FAIL`, `PROBE <id> PASS|FAIL` and `DONE <passed>/<total>`, each as Godot emits it. Run with `pwsh -NoProfile -File tools/gate.ps1 run --no-markers --stall 600 --log .tmp/godot-export.log --slot heavy --timeout 1800 -- pwsh -NoProfile -File godot/export.ps1`.
- `tools/test-sign-macos.ps1`: tests `tools/sign-macos.ps1` against stub macOS tools (Windows only). Run with `pwsh -NoProfile -File tools/gate.ps1 run --log .tmp/test-sign.log --slot light --timeout 900 -- pwsh -NoProfile -File tools/test-sign-macos.ps1`.
- `tests/GodotXaml.LanguageServer.Tests` (net10.0, xunit.v3): the server driven in process over in-memory pipes (`ServerHarness`) with a manual debounce scheduler, so no test asserts on wall-clock time. Run with `./run.ps1 test`.
- `tests/GodotXaml.Cli.Tests` (net10.0, xunit.v3): the CLI run in process through `CliProgram.Run` with string writers and per-test temp folders (`CliProgramTests`); tests that change the process's current directory run in their own non-parallel collection (`WorkingDirectoryTests`). Run with `./run.ps1 test`.
- `tests/fixtures/values/`: the expected value text, written by `tools/value-fixtures/` in `canonical/`, `loose/`, `floats/` and `format4/` (the saver's text with compat off); `tests/GodotXaml.Core.Tests/Values/` reads it.
- `tests/fixtures/scenes/`: `.tscn` and `.tres` files saved by Godot's text saver, written by `tools/scene-fixtures/`; `tests/GodotXaml.Core.Tests/Tscn/` reads it.
- `tests/fixtures/xscn/`: hand-written `.xscn`/`.xres` files read by `XscnWriterTests`: `canonical/` (written back byte for byte) and `format/` (`.in.xscn`/`.out.xscn` pairs of the canonical rewrite).
